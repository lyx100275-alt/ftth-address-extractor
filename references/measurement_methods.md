# 测量方式架构

> **核心思路**：测量方法按**测量原理**命名，是一个与项目无关的**方法池**——读取标注、区间法、竖线法、V型计算。**没有统一模式**：每张新图纸按探查信号逐步骤选方法，同一张图不同步骤可用不同方法，同一张图不同楼栋也可用不同方法。**禁止用小区名冠名测量方法**；`methods/` 目录下的图纸档案（按图纸组织形态分类）仅作参数参考，不含任何具体项目数据。标准四步流程（探查→解析→自检→出表）不变。

## 零、方法池（四种测量方法，按原理命名）

> **单一真源**：四种方法（读取标注 / 区间法 / 竖线法 / V型计算）的完整对照表（测什么 / 判定依据 / 输出）、子任务→方法选择表，以及竖线法「端点直推（三步走）」与 V型计算的具体算法，**统一维护在 SKILL.md「测量方式架构」一节**，本节不重复，以免两处漂移。本节只保留该节未覆盖的增量：各方法依赖的**信号名**。

**各方法依赖的信号**（信号定义见 `methods/signals.json`，决定该方法在本图是否可用）：

| 方法 | 依赖信号 | 信号缺失时的去路 |
|---|---|---|
| 读取标注 | 对应标注存在（**层内形态**：`X户`、`Xm*N`；**图签形态**：栋级 `N#楼` + `N层/M户` + `N单元`） | 换用区间法（户数锚点计数：**优先家居配线箱图标**，其次皮线标注） |
| 区间法 | **`floor_scale`**（楼层线或楼层标注可建成连续楼层带）；户数锚点**优先 `box_icon_annotation`**（家居配线箱图标：每户一个、贴皮线末端），无图标时才用皮线标注 | 无楼层刻度则无法定位 —— V型计算与竖线法一并失效（见下） |
| 竖线法 | `dedicated_wire_layer` + `vertical_bus_traceable` + **`floor_scale`** | 换用 V型计算 |
| V型计算 | `fiber_length_vshape` + **`floor_scale`**（谷底定层走区间法） | 换用竖线法 |

> **`floor_scale` 是三法共同前置**：区间法（户数 / 安装楼层）、竖线法三步走第②③步（用区间法测安装楼层与断头端点所在层）、V型计算的谷底定层**都走它**。缺 `floor_scale` ⇒ 三者一律不可用，只剩纯文字直读（*读取标注*）。**覆盖范围**的读取标注形态由 `cover_range_annotation` 承担（图上直写箱体覆盖起止层，可作判据）。

> **「读取标注」的形态**：① **层内形态**——逐层标注（`X户` / 箱号 / `Xm*N`）；
> ② **图签形态**——标题栏/图签层的**栋级**标注（`N#楼` + `N层/M户` + `N单元`，按固定几何偏移与楼名配对）；
> ③ **覆盖形态**——图上直写箱体覆盖起止层（如 `覆盖 -1F~9F`，信号 `cover_range_annotation`），是**覆盖范围唯一可直读**的路子。
> 三者**测量原理相同（直读文字）**，仅标注位置与聚合粒度不同——**都不是独立方法**，方法池仍为四种。

**禁止跨用途混用**：竖线法/V型计算只测覆盖楼层；区间法只测户数与安装楼层；严禁用「按安装楼层排序切分」当覆盖判据。
**结果拼装**：读取标注/区间法给出「箱在几楼+每层几户」，竖线法/V型计算给出「箱覆盖哪些层」，叠加得出「箱覆盖了多少户」。

## 一、信号驱动选方式

### 1.1 什么是"信号"

信号是图纸的**固有结构特征**，描述"图怎么摆"，不是"图上写什么"。

**结构条件（信号）** vs **内容参数** 的关键区分：

| 维度 | 结构条件（信号） | 内容参数 |
|------|-----------------|---------|
| 描述 | 图怎么摆 | 图上写什么 |
| 举例 | 每楼信息是否聚成独立簇 | 箱号格式FLxx-FXxx |
| 作用 | 决定能否使用某种测量方式 | 探查阶段动态发现，传入脚本参数 |
| 是否作为筛选条件 | ✅ 是 | ❌ 否 |

### 1.2 探查阶段的架构职责

探查是"测量的指挥"——自己不测量，只定怎么测。探查阶段需判断的结构信号：

1. **独立簇信号**：每栋楼的全部信息是否聚成独立簇（标题是簇内锚点 vs 标题是图框角标签）
2. **标题紧贴信号**：标题是否紧贴其所属内容（vs 标题与内容分离、距离远）
3. **楼层y独立信号**：楼层y坐标是否楼内独立有效（vs 楼层线贯穿所有楼、y坐标全局共享）
4. **标题间距信号**：相邻楼栋标题x间距是否大于候选区宽度（vs 标题间距过小、窗口互相污染）
5. **共享图纸信号**：标题中是否包含多个楼栋号（如"7#、8#、10#住宅光纤入户系统图"）。结构相同的楼栋共享一张图纸——画一遍代表多栋，信息不遮挡不混杂。此信号影响楼栋分组策略：不需拆分，而是读一次·按标题列出的楼栋号复制N份。

### 1.2.1 信号层级

信号分两层，避免混淆：

| 层级 | 作用 | 信号举例 |
|------|------|---------|
| **全局筛选信号** | 决定整张图用哪种测量方式组合 | cluster_layout（楼-簇独立组织）、dedicated_wire_layer（专用电信连线图层）|
| **步骤内信号** | 决定某一步内部用哪个候选（primary / alternate） | household_annotation（户数标注）、fiber_length_vshape（皮线V形）、vertical_bus_traceable（竖干可追踪）、shared_drawing（共享图纸）|

全局筛选信号决定"整张图的布局类型"，步骤内信号决定"某个子步骤用哪种具体方法"。两者不冲突。信号的定义、检测方法为本技能的不变量，统一登记在 `methods/signals.json`；每张图纸的画像只引用信号名并声明其 `status`（`present`/`absent`/`variant`）与 `evidence`。

### 1.3 四步中真正因图纸换方式的主要集中点

- **探查**：始终执行，产出图纸画像
- **解析**：主要变化点——楼栋分组方式、单元分组方式、覆盖判定方式都可能因信号不同而换
- **自检**：基本不变（交叉校验逻辑通用）
- **出表**：基本不变（只组装不判定）

## 二、图纸类型 A：楼-簇组织型图纸

> **本节为图纸类型档案，非方法绑定、非项目绑定**：该组合适用的是「楼-簇组织+户标注+皮线米数V形」这类图纸特征。

### 2.1 适用条件（结构信号筛查）

楼-簇组织类图纸适用于满足以下全部结构条件的场景：

| 信号 | 条件 | 典型实测 |
|------|------|---------|
| 独立簇 | 每栋楼全部信息聚成独立簇 | ✅ 每楼一个"X#楼光缆布放示意图"标题，图形在标题附近 |
| 标题紧贴 | 标题紧贴其所属内容 | ✅ 标题正下方/旁边就是该楼的分纤箱/楼层/皮线标注 |
| 楼层y独立 | 楼层y坐标楼内独立有效 | ✅ 每楼楼层标注y坐标独立，不与其他楼混叠 |
| 标题间距 | 相邻楼栋标题x间距 > 候选区宽度 | ✅ 楼栋间距足够大，候选窗口不互相污染 |

### 2.2 三个测量信号（该图纸可行根因）

此类图纸便于测量，因为以下三个信号都在：

1. **每层标注了户数**（“X户”文字标注）——读取标注直读，无需数皮线
2. **皮线长度呈V形结构**——V型计算可用（低箱谷底+高箱谷底各自V形，交点即分界）
3. **标识楼层的横线是连续横线**——但竖干可能混在非电信图层（如建筑线同层），**竖线法信号不可用**，覆盖判定按信号选 V型计算

### 2.3 各步骤测量方式

| 步骤 | 方式 | 说明 |
|------|------|------|
| 探查 | 标准探查（Step 1a） | 图层/文字类型/坐标尺度/线段检查 |
| 解析-楼栋分组 | 标题锚点+x中分 | 找"X#楼XX图"标题，按标题x坐标中分确定归属范围 |
| 解析-单元分组 | 分纤箱x锚点+阈值聚类 | 以分纤箱标注x坐标为锚点，合理阈值内归属同单元 |
| 解析-覆盖判定 | 按信号选（V型计算 或 竖线法）→ 待确认 | 按信号选，不设固定优先级：皮线有V形→V型计算；竖干干净→竖线法；两信号均在则双跑互证；均不可信→待确认（详见 coverage_rules.md） |
| 自检 | 标准交叉校验 | 两类图纸交叉验证/楼层完整性/楼层归属方法/楼层数两方校验/户数皮线匹配/安装楼层/分光方式/覆盖范围/户级归属/矛盾检查（详见 SKILL.md Step 2） |
| 出表 | gen_addressbook.py组装 | 只组装不判定 |

### 2.4 脚本参数（实测值，供参考，换图须按探查覆盖）

脚本默认值仅供参考，换新图纸时先按Step 1a探查结果覆盖参数。主要参数：

- `--text-layer`（文字层，按探查实测）
- `--text-type TEXT,MTEXT`（文字类型，按探查实测）
- `--title-pattern "X#楼.*图"`（楼栋标题正则）
- `--floor-pattern`（**留空即 None，用内置统一解析**，支持 `3F/17F/-1F/B1/B2/WF`；勿传 `(-?\d+)F`，会让 `B1` 整层静默消失）
- `--hu-pattern "X户"`（户数标注）
- `--fx-pattern`（分纤箱编号，按探查实测）

## 三、图纸类型 B：共享图纸 + 混合布局型图纸

> **本节为图纸类型档案，非方法绑定、非项目绑定**：该组合适用的是「共享图纸+无户标注+无皮线米数+独立竖干图层」这类图纸特征。

### 3.1 结构信号差异（与楼-簇组织对比）

共享图纸型与楼-簇组织型在结构上根本不同：

| 信号 | 楼-簇组织型 | 共享图纸型 |
|------|---------|------|
| 组织方式 | 楼-簇（每楼独立簇） | 共享连续结构+分离标签 |
| 标题角色 | 簇内锚点（紧贴内容） | 图框角标签（与内容分离） |
| 楼层线 | 连续横线（楼内独立） | 贯穿所有楼（全局共享） |
| 标题间距 | 足够大 | 可能极小，窗口互相污染 |

### 3.2 三个测量信号缺失情况

1. **户数标注**：无“X户”标注——读取标注信号缺失，改用区间法（皮线标注/INSERT 落楼层带计数），户数以系统图为准
2. **皮线米数V形**：无皮线长度数据——V型计算信号缺失，覆盖判定改选竖线法
3. **连续横线**：横线中间断开——但竖干在独立电信图层，竖线法信号可用

### 3.3 共享图纸模式（2026-09-06 认知修正）

**之前的误判**：助手发现多个楼栋的楼层标注 x 坐标重叠，判定为"标注混杂、无法区分归属"，将此视为卡点。

**实际原因**：这几栋楼结构相同、布线方案相同，画图人画一张代表多栋，标题把多栋并列写出（如"A#、B#、C#住宅光纤入户系统图"）。图上只画了一遍楼层、分纤箱、皮线——因为这几栋楼**就是一样的**。图上没有互相遮挡的文字和符号，信息清清楚楚摆在那里。

**这不是"标注混杂"，而是共享图纸的正常行为。** 正确的处理方式：

1. 读标题，识别出标题里列出的共享楼栋号
2. 把图上的分纤箱、楼层、户数等**解析一份**
3. **按共享楼栋数复制**，分别挂到各栋楼名下

**此信号（shared_drawing）不依赖横线连续性**。横线连续与否影响的是覆盖判定的连线追踪（步骤内信号），与共享图纸的识别和处理无关。

**共享图纸的单元列数换算**：分纤箱总图按“楼栋×单元”列出全部分纤箱，而共享系统图只画1列。自检比对单元数时须先换算：总图单元数 = 共享楼栋数 × 每栋单元数，系统图所画列数对应“每栋单元数”而非总数。复制时把所画的1列挂到每栋楼各自的对应单元名下，不得误挂为同一栋楼的多个单元。

### 3.4 楼栋/单元归属判定方法

#### 问题

一张系统图上有多栋楼，如何确定每个 INSERT/皮线实体归属哪栋楼、哪个单元？

#### 一般法（区域归属法）——通用主干

1. 用图标题文字坐标作为锚点，确定每栋楼的图幅区域边界
2. 对每个实体，判断它落在哪个楼栋的区域内
3. 区域内再按 x 列（一单元一列）拆分单元

此法是归属判定的通用框架，适用于所有图纸布局。

#### x 列法（特例 / 快捷路径）

当各楼栋的 x 列投影互不重叠时，区域判定退化为"比较 x 坐标"：

- 直接按 INSERT 的 x 坐标分列，一列 = 一个单元
- 每列的 INSERT 数 = 该单元户数

**适用前提**：相邻楼栋 x 列间距足够大（不重叠）。

**优势**：只读实体自身坐标，不依赖标题文字完整性，鲁棒性高。

**局限**：x 列重合时失效。例：某两楼 x 坐标仅差 1，光靠 x 无法区分。

**与一般法的关系**：x 列法不是与一般法并列的另一种方法，而是一般法在"x 方向投影分离"前提下的退化特例——此时区域判定等价于比较 x 坐标，不必再动用标题锚点。

#### 兜底法（x 分不清时）

当 x 列法无法区分时，退回完整的一般法：

1. **标题锚点**：读图标题文字坐标，圈定该楼的图幅区域（如"X#配套光纤入户系统图"@(x, y)）
2. **y 区间辅助**：结合实体 y 坐标判断楼层归属区域（如配套楼 INSERT 全在 B1~1F 区间、住宅楼在 8F 以上）
3. 两者结合裁定归属

#### 规则

- **一般法为主干**：区域归属是通用框架，x 列法是其特例；探查阶段先判断 x 列是否分离，分离则走快捷路径，否则走兜底法
- **禁止只沿一个维度搜索**：必须同时考虑 x 和 y 两个维度，禁止只搜一条竖列
- **搜索范围宁可大不可小**：按图框边界完整覆盖，截断会漏实体

#### 事故记录

| 事故 | 现象 | 根因 |
|------|------|------|
| 某楼误并入邻楼 INSERT 列 | 该楼若干层每层多算户数 | x 范围未严格限定，混入相邻楼竖列 |
| 相邻两楼 x 坐标几乎重合 | 只靠 x 无法区分两楼实体 | 需退回标题锚点+y 区间兜底 |
| 某楼只搜一条竖列（单一 x） | 只找到少量目标实体，漏大量实体 | 只沿一个维度搜索 |
| 某楼楼层线/INSERT 混入邻楼 | 邻楼虚增楼层和户数 | 未先用标题锚点确定图幅边界，邻楼实体落入搜索范围 |

#### 分带的适用边界（2026-09-16 实测，重要）

`compute_bldg_ranges_banded()`（`--title-band-tol`）解决的是**锚点网格**层面的串带 ——
把"甲带标题被当成乙带分界"消掉。它**不解决**文字/实体按 x 归属时的跨带泄漏：

- `count_households` 的文字归属是**纯 x 窗口**判断（`xmin <= x <= xmax`），未带 y 分带过滤；
- `cluster_by_x` 的列聚类同样只看 x，不含 y。

因此当配套行与住宅行的**标题 x 几乎重合**时（实测某图 7# 与 11#配套标题 x 仅差 0.7，
且同一 x 列的皮线 y 跨度横跨两带）：

| 跑法 | 现象 |
|---|---|
| 单带 | 配套行的锚点**切开了**住宅楼的 x 窗口 → 皮线列被切给配套楼（实测 7# 得空列） |
| 分带 | x 窗口随锚点网格变化，但**皮线列在栋之间搬家**，归属并未变可靠（实测 7#、9# 的皮线列互换） |

**结论**：这类图**不要**指望文字法给出逐栋户数 —— 把它当线索，以图标法/图签口径 + 用户裁决定案。
**修法方向**：让归属同时受 `(x ∈ 栋窗口) ∧ (y ∈ 该栋所在带)` 约束，
带 y 范围按相邻带 y0 中分（与 x 中分同构）。属**行为变更**（会改户数归属），须专项回归对拍交付表。

### 3.5 楼层归属方法：区间法

> **区间法统一管两件事**：
> 1. **每层户数**——皮线标注/INSERT 落在哪条楼层带就归属哪层
> 2. **分纤箱安装楼层**——分纤箱箱体/符号/编号文字落在哪条楼层带就归属哪层
>
> 两处共用同一套楼层带区间，方法一致，禁止与"最近楼层线法"混用。

#### 问题

判断系统图中 INSERT（家居配线箱/设备符号）归属哪一楼层时，之前隐含使用"最近楼层线法"——取离 INSERT y 坐标最近的楼层线，归属该层。

**此方法在 INSERT 分布不均匀时产生误判**。

#### 事故

某配套楼1F有5个INSERT，最下面2个越过1F区间中点、离2F线更近，"最近法"误判为2F。实际应归属1F（落在1F线与2F线之间的1F带内）。

其余住宅楼因每层 INSERT 均匀分布，两种方法结果恰好相同，未暴露问题。

#### 区间法（正确方法）

1. **按 y 坐标排序所有楼层线**，得到有序序列：y_0(B1) < y_1(1F) < y_2(2F) < ... < y_n(WF)
2. **定义楼层带**：相邻两条楼层线之间为一条带，第 i 条带 = [y_i, y_{i+1})，归属第 i 层
3. **判断 INSERT 归属**：对每个 INSERT 的 y 坐标，找到它落在哪条带内（y_i ≤ y < y_{i+1}），即归属该层
4. **边界处理**：落在最低楼层线以下（y < y_0）的 INSERT 不归属任何楼层，列为待确认项

#### 规则

- **楼层归属必须用区间法**，禁止用最近楼层线法
- **区间法同时测户数归属与分纤箱安装楼层**：户数与分纤箱的楼层定位共用"落在哪条楼层带"的同一套区间判定，保证两处口径一致
- **对 INSERT 分布不均匀的楼层重点复核**：偏移量可能超过层间距一半时，两种方法结果不同
- **楼层线来源**：从系统图 TEXT/MTEXT 楼层标注（B1/1F/2F/.../XF/WF）或楼层横线（LINE/LWPOLYLINE）提取 y 坐标。若两者均可直读，优先用文字标注的 y 坐标

**边界异常识别**：某层户数与相邻层显著不同时（如1F=4户而其余层均=2户），优先怀疑该层与相邻层的分界线（如B1/1F边界）附近 INSERT 被误归——把边界 y 坐标与两侧 INSERT 分布列为参考线索交用户裁决，不得自行改派归属。

#### 3.5.1 户数实体来源：家居配线箱图标（贴皮线末端判据）

区间法测「每层户数」时，**落到楼层带里的"实体"有三种**，按本图实际提供的那一种取用：

| 户数实体 | 图面表现 | 判据 | 可靠性 |
|---|---|---|---|
| `X户` 标注 | 每层直写「N户」 | 直读 | 最高 |
| **家居配线箱图标** | 每户一个入户端图标，**紧贴皮线图元端点** | 几何贴合（见下） | 高；**零重复** |
| 皮线标注（`1芯皮线光纤` 等） | 每条皮线一行字 | 文字计数 | 中；**须按 (x,y) 去重** |

**为什么优先用图标**：图标是**物理实体**（每户必有的入户端），竣工图必须表达；
皮线标注只是线路示意，可省可合并，**且实测存在同坐标重复绘制**（云峰 335 → 331，
曾让某楼户数虚增 4 户，而"总数 == 总数"式守恒校验抓不到）。

**判据**（`scripts/count_box_icons.py`；子命令 `count-box`，旧名 `count-hdd` 仍可用）

```
家居配线箱图标 ≡ 落在「皮线图元端点」固定小偏移之内的候选图标
```

- **皮线图元**：图层名命中 `wire / 皮线 / fiber / 光缆 / 光纤`（排除 `cabletray / 桥架`）的
  LINE 与 LWPOLYLINE/POLYLINE；也可用 `--wire-layer` 显式指定。取其**首、末顶点**为端点。
- **候选图标**：默认全部 INSERT 块引用；`--include-square` 追加「小闭合方块」
  （4 顶点闭合多段线，宽高在给定范围内、长宽比 ≤ 3），覆盖"只画方块、不插块"的图纸。
- **容差随图量测、不写死**：取"候选 → 最近端点"距离直方图的**最低显著峰**作基准，
  容差 = 基准 × 1.5（钳制 [2, 30]）。实测云峰基准恒为 **4.04**（331/331 命中）。
  有关键词命中的候选时优先用它作种子定标；无关键词时退化用全部候选并抬高显著性阈值。
- **图区过滤**：候选必须落在"楼层刻度列的 y 范围 ± pad"内。这一步是必需的——
  平面图区的线管走线（`WIRE-*` 等）也含 `wire` 字样，不过滤会把平面图图标当成"贴末端"吞进来。
- **物理列切分**：先按 x 容差（默认 1.0）聚类（块对齐差异会让同一列的 x 抖动 0.1~0.5），
  再按 y 断口（默认 40，约一个层高）切 run（共享图纸上下两行同 x 带必须分开，否则列会串）。

**分级（决定是否计入户数）**

| 级别 | 条件 | 处置 |
|---|---|---|
| **A** | 在图区内 + 贴末端 + 有文字（`家居配线箱` / `HD` / `HDD` / `多媒体箱` …） | 计入，可直接采信 |
| **B** | 在图区内 + 贴末端 + **无任何文字** | 计入（纯几何判据）——"图标只是个方块"的情形 |
| **C** | 有文字但不在图区、或不贴末端 | **不计入**；全部列出供人工核对（典型＝平面图示意图标） |
| — | 无文字且不贴末端 | 丢弃 |

**边界（与既有裁定相容）**

- **楼层平面图**里的同名图标不作户数依据（2026-09-13 裁定不变）。本方法不是靠"图层名/块名"
  区分两图区，而是靠**几何**：平面图图标周边没有系统图那种皮线图元，不可能贴系统图皮线末端
  → 自动落 C 级。故本方法与「不读楼层平面图」**相容，而非推翻**。
- `*N` 乘数标注（如 `*16`）**不得自行相乘**：脚本只输出 `待裁决_乘数标注`，
  含义与落层口径由用户裁决后再改数。
- **必须与皮线口径并跑互证**：`count-box` 与 `count` 逐列逐层比对，不一致即停止交用户。
- **前置条件：图标必须是「每户一个」（2026-09-14 柳辛庄实测新增，本法的最大盲区）**：
  有些图（**包括系统图本身**）把图标画成「**每单元每层一个**」的示意画法，
  每层配一个 `xN` 乘数标注说明该点代表几户，且**全图没有入户皮线图元** ——
  此时判据"贴皮线末端"根本不成立，脚本按门禁退出（rc=2）并打印诊断，**不得当成功消费**。
  判据（图纸自身可判，无需人工看图）：
  ① 同一 x 列内相邻图标的 Δy 是否**恒等于一个层高**（恒等 → 每层 1 个，是层/单元级）；
  ② 图标总数 ≈ Σ(层数×单元数)（层/单元级）还是 ≈ Σ(层数×单元数×每层户数)（户级）。
  柳辛庄 1-4：449 图标 / Σ(层×单元)=661 / 列内 Δy 恒为 15600·17550（零例外）；
  5-9：356 图标 / Σ(层×单元)=624 / 同理 —— 两图均**不适用**本法，改走图签口径。

**验收（云峰，150MB DXF）**：图标口径 331 户 / 皮线口径（去重后）331 户 /
纯几何口径（禁用关键词）331 户 —— 三路**坐标集合一致、13/13 列逐层零差异**；
平面图 126 个同类图标全部落 C 级不计入。

#### 3.5.2 楼层标注自洽性：同形文字的静默污染（2026-09-16）

**判据（通用，与项目无关）**：把某区域内的楼层标注收成「楼层名 → y」表时，先做两条检查：

1. **同名多址**：同一个楼层名出现在两个以上不同标高。同一区域内一个楼层只应有一条楼层线；
   出现多址即说明这组标注混入了非楼层文字。
2. **次序倒挂**：按 y 升序排列后，楼层数值须单调不减；倒挂说明混入了不属于本区域楼层序列的标注。

**为什么必须喂未去重的原始列表**：建表实现通常是 `floor_marks[txt] = y`（字典覆盖），
多址会被**静默合并成一条** —— 既不报错也不进待确认清单，属最危险的一类缺陷；
拿字典去检查等于没检查。

**典型命中场景（与文字写法无关）**：路由图 / 端子图上以 `B1`…`B9` 标端口，与
`parse_floor_label` 认可的地下层写法 `B<数字>` **同形**，被一并收进楼层表后
**静默污染区间法归属**（实测把分纤箱归到了不存在的 `B9` 层）。
**修法方向**：给归属加区域约束（bbox，或"总图区 / 系统图区"分带），
**不要**改成禁止 `B<数字>` 写法 —— 那会误杀真实的地下室楼层。

**实现**：`ftth_common.floor_mark_conflicts(items, y_tol=0.001, max_report=5)`，返回冲突描述列表。
已接线 `count_households.py`（写入 `楼栋[栋].楼层标注冲突` 与 `自检.楼层标注冲突` + 控制台 warning）。
**只报不拦** —— 该类脚本的输出定位是"线索非结论"，拦死会误伤正常图。

### 3.6 共享图纸型已解决的问题

共享图纸模式解决了"多栋楼只画一份"的认知问题，以下问题均已解决：

- **共享图纸 + 独立图纸混合**：已解决。共享图纸读一份复制N份，独立图纸逐栋解析。详见 §3.4 楼栋/单元归属判定方法
- **无户数标注时的户数统计**：已解决。**优先用家居配线箱图标法**（`count_box_icons.py`，判据＝图标贴皮线末端），按区间法归属楼层；**图上存在图标时不再数皮线**（2026-09-16 用户裁决）。图标不可用时（图上无图标 / 图标为「每单元每层一个」的示意画法 / 门禁 rc=2）才回落到**皮线计数法**（`count_households.py`，按 (x,y) 去重）。无论走哪一路，都与『X户』直读值（若有）对账，不一致交用户。详见 §3.5.1（**含前置条件：图标须为「每户一个」，否则本法不适用**）
- **无皮线长度数据时的覆盖判定**：已解决。连线追踪走不通、V形计算也不行时，覆盖判定通过竖干断口/端点直推法（覆盖表仅作参考线索，不作覆盖判据）。户数与覆盖拼装时，户数一律取系统图读数
- **两法分立拼装（核心方法论）**：全程只用两种测量法，各测各的、最后拼装——**竖线法**沿分纤箱接线竖干追踪、以竖干物理断口定覆盖分界，测「分纤箱覆盖到哪些楼层」；**区间法**（楼层带归属）测「每层户数」与「分纤箱安装楼层」。两法结果叠加：区间法给箱位与户数，竖线法给覆盖层，拼出「分纤箱覆盖了多少户」。任何一步不得把两法混用
### 3.7 图签形态的几何容差量测：方向约束 + 等权综合距离

图签（标题栏）形态把「楼名 / 层户 / 单元」三类标注散落为互不相干的文字实体，只能靠
几何偏移把它们串起来。这 6 个容差随图纸坐标尺度变化，由
`scripts/probe_titleblock_tolerances.py` 从图纸自身量测（也可让
`read_titleblock_households.py` 缺省自适应）。

量测「层户 ↔ 单元」的 Δy 时，**必须施加方向约束，并在候选中按等权综合距离取**：

| 判据 | 内容 | 实测结果 |
|------|------|----------|
| ① 方向（必加） | 只在单元标注的**上方**（`层户y > 单元y`）取候选 | 不加则地块A「排间距 35906 < 块内间距 46319」，最近邻取到**下一排**层户，量出 **-35906 的负容差**；负窗口让该栋全部单元配不上层户 → 静默丢户，不自我暴露 |
| ② **\|dx\| + dy 等权**（取候选） | 在上方候选中按 x 距离与 y 距离**等权相加**最小者取 | 4 个歧义点**全部选对** ✓ |
| ✗ 只用「x 最近」 | — | 4 点**错 2 个**：地块A 错的候选 dx=26219 < 对的 31900，但其 dy 差 3 倍 |
| ✗ 只用「y 最近」 | — | 4 点**错 2 个**：地块B 错的候选 dy=33860 < 对的 43443，但其 dx 差 20 倍 |

> **实测对照**（验证图：一张多地块混排竣工图）：改用等权后四个地块的单元↔层户配对率全部 100%
> （此前 16/20、12/24），全图 `unit-dy` 窗口 **[41179.7, 50234.9]** 完整覆盖四段窗口。
> ⚠️ 只加「x 最近」而不等权，窗口会收窄为 [44713.1, 49057.1]，把真实值 **43443.5 挤出主簇**，
> 自适应路径从 24 栋掉到 **22 栋**——**判据改动必须端到端复跑，只看配对率会误判为成功**。

**量测结果自检**：窗口若自相矛盾（`lo >= hi`）或**跨越 0**，说明配对方向相反或配错，
一律按失败退出（`ToleranceEstimateError`，退出码 2），不得静默输出——跨零窗口会把
「另一侧」的标注也框进来，产出的覆盖数据看着正常，实际已串楼。

> **为什么不做「多地块各用一组容差」**：实测分地块量测样本少、统计不稳（配对率曾低至
> 12/24，`unit_dx` 量到 80 万），而全图一组的窗口已覆盖全部地块的真实配对（各段窗口均
> 落在全图窗口内）。探针的 `--band` 因此**只做交叉校验**：逐段量一次，若有段落的窗口落在
> 全图窗口之外（该段会丢户）才告警，并给出「该段单独出表」的命令。

|------|------|------|
| `methods/signals.json` | **不变量**（跨图纸共享） | 每个信号的名称、`description`、`detect_method`、`applies_to`（适用步骤）、`level`（全局/步骤内）、`requires`（前置信号）；另含 `status_values` 枚举 |

### 4.3 字段说明

| 字段 | 说明 |
|------|------|
| `kind` | 固定为 `drawing_profile`，表明这是图纸类型档案而非方法或项目 |
| `signals.*.status` | 必须是 `signals.json` 的 `status_values` 枚举值（`present`/`absent`/`variant`），**不得写中文自由文本** |
| `signals.*.evidence` | 该状态下必须写清实测依据；`variant` 时必须写清与标准定义的差异 |
| `steps.*.candidates[]` | 候选方法列表，每项含 `role`（`primary`/`alternate`）、`method`（限方法池命名）、`requires`（依赖的信号名）、`script`、`params`。**取代旧的 `primary/fallback_1/fallback_2` 降级链**——降级顺序不再由编号隐含，而由 `requires` 是否成立决定 |
| `steps.*.cross_check` | **两个候选的 `requires` 同时成立时必须并跑交叉比对**（不再"任选其一"）。不一致不得自动择一 |
| `steps.出表` | 只组装不判定 |
| `param_source.must_probe` | 随图纸坐标尺度变化的检测类参数。**不设固定默认值**——其中能从图纸自身量出的改为**缺省自适应**（竖线法的层高比例容差、图签形态的 6 个几何容差），量不出的仍由 `require_params` 报错退出（exit 2） |
| `param_source.algorithm_defaults` | **不随图纸坐标尺度变化**的算法常数（阈值/容差），可沿用。注意判据是「是否随坐标尺度变化」，不是「名字里带不带容差」——本技能当前**没有**符合条件的常数：凡 x/y 距离类阈值都随层高变化（`y-tol`、`merge-tol`、`conn-tol` 等均已做成「比值 × 层高」自适应，特征值 2.0/3.0 只是量不出层高时的兜底），图签的 6 个几何容差同属检测类。给不出符合判据的常数时应留空表，**不得把兜底默认值填进来当「可沿用」** |

### 4.4 Step 1 → Step 2 交接契约 `handoff`（**两要素，逐项申报**）

> 用户裁定（2026-09-13，含当日语义修正；同日晚再裁定**不读楼层平面图**、三要素收缩为两要素）：
> 图纸向第二步（解析）传递的画像必须**至少**回答两项，每项给出明确答案。**这是申报制**：
> 有的图纸只给系统图、不给总图 —— **照样往下走**。
> `present`（有，附证据）/ `absent`（没有，附证据 + 降级路径）/ `variant` 三者**都不阻塞**；
> 只有 `unknown`（判不了）计入 `completeness.未作答` ⇒ `ok = false` ⇒ 入口 **rc=2 中止**。
> 本图未提供某子任务所需数据时，该命令 **rc=3 不适用**（跳过，非错误，不需重试）。

| 字段 | 回答什么 | 判定来源 |
|---|---|---|
| `①分纤箱总图.状态` | 有没有**集中**总图（对照表形态） | `fx_overview_map`：编号须与楼栋/单元标注**同行**才算对照表；若多数编号与 `X户`/`Xm*N` 同行 ⇒ 编号嵌在各楼系统图楼层表内 ⇒ `absent` |
| `①分纤箱总图.安装位置` | 编号同行的 楼栋 / 单元 / **安装楼层** 标注数（安装位置可读否） | `inspect_overview_map()` 量测；行距由本图楼层标注相邻 y 差量出，x 容差取主体 x 跨度 15% |
| `②系统图选法.{每层户数, 分纤箱位置（安装楼层）, 覆盖范围}` | 各用什么方法统计（**只申报方法，不出结果**） | `steps.解析.*.candidates[]` 中 `requires` 全部成立的**首个**候选；无可用候选时按前置信号实况分：**全部明确 `absent` ⇒ 申报 `absent` + 写 `降级`**；含 `unknown` ⇒ 未作答 |
| `②…分纤箱位置.安装楼层方法` | 安装楼层走直读还是区间法 | **随选定方法导出**：选定方法属「读取标注」⇒ `读取标注（编号旁直写安装楼层）`；属「区间法」⇒ `区间法（编号文字/箱符号落楼层带）`。**不得另行断言方法池里不存在的方法** |
| `② 必备性` | 系统图是否可用 | 「分纤箱位置（安装楼层）」「每层户数」**缺任一 ⇒ `不可解析` ⇒ rc=2**；「覆盖范围」可 `absent` + `降级`（不阻塞）。注：此处的 `降级` 是**缺项替代校验路径**的契约字段名；方法池内各方法同级、按信号路由，无主次/降级之说（2026-09-13 用户裁决） |
| `completeness.ok` / `未作答` / `不可解析` / `缺失项及降级路径` | 申报是否完成 / 唯一阻塞项 / 无任何可解析依据 / 本图缺项的替代校验 | `ok = 未作答为空 且 不可解析为空`；**`absent` 不进 `未作答`**（absent 只进缺失项 + 降级路径） |

### 4.5 总图判据的实测背景（外移自 SKILL.md，2026-09-17）

旧判据是「编号 + 楼栋 + 单元同图」的**数量共现**，对"编号随楼分散、嵌在各楼系统图楼层表内"的图纸**必然误判为有总图**：
实测某图 17 条编号 x 跨度占图纸主体 **75%**、与单元标注 x 重合 **94%**、且 **100%** 与 `X户`/`Xm*N` 同行
（即编号就写在楼层表里）。故现行判据改用**对照表形态**：编号须与楼栋/单元标注同行（`|dy| ≤ 本图行距`，行距由本图楼层标注相邻 y 差量出；`|dx| ≤ 主体 x 跨度 15%`）；若多数编号与 `X户`/`Xm*N` 同行 → 判 `absent`。
## 五、新图纸的处理流程（外层接入 SOP —— 单张图的执行仍是四步，本节用于「接入一类新图纸」）

1. **探查**：对新图纸进行Step 1a探查，判断结构信号与标注情况（方法选择依据）
2. **选法**：按方法池的子任务→方法选择表，逐步骤选定方法组合（读取标注/区间法/竖线法/V型计算），不预设「某项目=某方法」。选法的产物是 **Step 1 → Step 2 交接契约 `handoff`（两要素，§4.4）** —— 两项**逐项申报**即可进入第 4 步：本图缺的要素报 `absent` **不算缺陷**（按 §4.4 降级路径，以现有图纸为准）；只有 `unknown`（未作答）才 `completeness.ok=false` → 入口 rc=2
3. **对比**：与 `methods/` 下的图纸档案对比参数，按探查结果覆盖
4. **执行**：按选定方法跑通完整四步流程
5. **沉淀**：参数与信号实测结果写入新的 `manifest.json`（作为图纸类型档案），更新SKILL.md图纸类型参考表
6. **回归**：有真值表时用 verify_coverage_truth.py 反查验证；无真值表时新发现交叉校验
