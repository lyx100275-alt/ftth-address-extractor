### Step 2: 自检

解析完成后进行内部交叉校验：

- **两类图纸交叉验证（2026-09-08 用户确立；2026-09-13 裁定去掉楼层平面图，必须执行）**：FTTH图纸中两类图纸必须互相验证，不以任何一方为准：
  1. **总图**（光交和分纤箱总图，若有）：分纤箱编号、位置、对应光交盘号和纤芯号
  2. **楼宇系统布线图**：各单元分纤箱安装楼层、覆盖楼层、出纤数量（**户数唯一来源**）

  - 两者数据一致 → 可认为正确
  - 两者出现矛盾冲突 → 停下来交用户复核，禁止自行选择任何一方为准
  - **户数以系统图为准**（2026-09-13 裁定；2026-09-14 精确化）：**楼层平面图**的 INSERT 数量是示意画法（一个户型只画一个），不作户数依据；而**系统图内**的「家居配线箱图标」在**每户一个**时是真实表达，可用 `count_box_icons.py` 计数（判据＝图标贴皮线末端），两者靠**几何判据**自动分开，不靠图层或块名。**但"每户一个"必须逐图验证**（2026-09-14 柳辛庄反例：系统图本身也可能画成「每单元每层一个」＋`xN` 乘数标注，且全图无皮线图元，此时本法读数＝层×单元、**不是户数**）——凡图上出现 `*N` / `xN` 乘数标注（如画1个HDD+`*16`代表16户），**该处图标数 ≠ 户数**，必须交用户裁决含义与落层口径后再改数。
  - **不读取楼层平面图**（2026-09-13 用户裁定）：户数、楼层归属等一切数据均不取自楼层平面图，全程只看总图（若有）与系统图。
    「不读平面图」与「可用系统图家居配线箱图标」**不冲突**——图标法自带几何判据（图标必须贴系统图皮线末端），平面图图标不满足该判据，被自动分离在 C 级且不计入。

- **一体化闭合核查（2026-09-16 新增，自检第一步）**：先跑 `inspect_closure.py`（或 `ftth.py inspect`），
  一次出齐七项：楼栋单元全貌与楼号断号 / 分纤箱安装楼层口径分布（null 即 FAIL）/ 安装楼层双源交叉
  （parse vs coverage，不一致即 FAIL）/ FX 编号坐标双向核对（需 geom 缓存）/ 楼层表直读清单 /
  覆盖闭合（缺线索、安装层不在覆盖集合内即 FAIL）/ coverage 顶层自检与需人工裁决透传。
  退出码 0/2，**有 FAIL 不得出表**。清单内事项**禁止再临时编写 `inspect_*.py`**——
  实测某会话串行写了 7 个一次性核查脚本、内容互相重叠，是当轮最大耗时项。
- **楼层完整性**：楼层数是否连续、有无异常缺失或混入（如远处孤立标注被误归）
- **标题重复检查**：同一楼栋标题在图中出现多次时，必须标记为可疑，不得仅凭标题文字判断区域归属。应通过 INSERT 块坐标范围、内部文字内容（如功能房间标注）交叉核实实际归属。标题误标是图纸质量缺陷，仅凭标题会导致区域归属错误
- **楼层归属方法校验**：确认使用区间法（非最近楼层线法），对 INSERT 分布不均匀的楼层重点复核
- **楼层数两方交叉校验**：系统图楼层线数与 INSERT 列覆盖楼层数两者必须一致，不一致则暂停（详见 [visual_model_lessons.md](references/visual_model_lessons.md) §8）；有分纤箱总图时另与总图安装楼层标注比对
- **单元列数交叉校验**：系统图每栋楼所画单元列数须与分纤箱总图单元数比对。共享图纸模式下先换算：总图单元数 = 共享楼栋数 × 每栋单元数，系统图只画其中一份。换算后一致 → 按共享图纸读一份复制N份，但“各栋结构确实一致”仍列入待确认项；换算后不一致 → 直接列为待确认项

- **户数/皮线匹配**：1F以上每层均有户数和皮线标注；-1F/-2F无户数标注属正常（视为无住户，见Step 1c负楼层说明）
- **户数口径优先级（2026-09-16 用户裁决，取代 2026-09-14 的「双口径并跑互证」）**：**图上存在家居配线箱图标（每户一个、贴皮线末端）时，优先数图标、不再数皮线**（`count-box`）；图标不可用（图上无图标 / 图标为「每单元每层一个」的示意画法 / 门禁 rc=2）时才回落到皮线计数（`count`）。
  - 图标口径与 `X户` 直读值（若有）不一致 → 停止，把双方数值 + 坐标交用户，禁止自动择一；
  - **图标口径零重复**（实测全图插入点零重复），这是它优先于文字标注的原因；
  - 若两口径仍都跑了而结果不一致，同样暂停交用户，不得自动择一；
  - **皮线口径若启用，必须先按 (x,y) 完全重合去重**（实测某图 335→331：同一坐标重复绘制会让户数虚高，而"总数==总数"式守恒校验抓不到）。
- **分纤箱安装楼层**：口径B的需确认y坐标关联距离在合理范围内
- **分光方式**：DXF无分光比文字标注时，将已知芯数关系作为线索列给用户裁决，禁止自行推断
- **覆盖范围**：**按信号选方法，不设固定优先级、不构成降级链**——竖线法（`scripts/analyze_coverage.py`，需干净竖干连线）/ V型计算（`scripts/analyze_coverage_vshape.py`，需皮线米数 V 形标注）；**两信号均在时两法必须并跑比对**，结果不一致列入待确认，不得自动择一；两法均不可信时才交用户裁决。详见 references/coverage_rules.md
- **安装层两来源校验**：图上存在「N号楼M单元K层」直读标注（probe 信号 `fx_location_annotation=present`）时，必须提取并与 V型/竖线法的安装层判定比对；**不一致时并列证据交人裁定，不得以任一方自动为准**（直读标注可能笔误，几何判定可能分带/配对错位）
- **多地块图纸**：probe 检出地块/分带标注时，图签提取与覆盖判定应按带分别运行再合并；同名楼冲突值来自不同 y 簇时图签脚本会提示「疑似跨地块同名楼」，不得忽略该提示直接出表
- **户级归属**：
  - 单箱单元：本单元所有住户楼层均归属该分纤箱（直读）
  - 双箱单元：按解析阶段判定的覆盖范围分配（竖线法/V型计算/待确认，详见覆盖规则）
  - **双箱分界层户级归属**：若用户确认的覆盖分界导致同一层可能横跨两个分纤箱，且DXF无法区分同层各户归属哪个分纤箱时，**必须列为待确认项**
- **守恒校验（2026-09-11 新增，必须做）**：出表行数必须等于源户数之和。任何"源户数 N / 出表 M（M < N）"这类不守恒都必须**报错停止**，不得只打印生成行数就当作通过。典型丢失原因：楼层正则不认 `B1`（整层丢）、共享图纸复制份数算错。
- **覆盖判定依据完整性（2026-09-11 新增）**：逐个分纤箱检查三字段是否齐全（`覆盖楼层` / `判定依据` / `依据来源`）。缺失即列入待确认项。
- **覆盖范围重复检测（2026-09-11 新增）**：同一单元内若多个分纤箱给出**完全相同**的覆盖楼层列表，判定为异常——这是旧算法的典型症状（取了"附近全部竖干"的 min~max，把断口两侧合并了），必须复核，不得直接采用。
- **箱位来源检查（2026-09-11 新增，必须做）**：逐箱检查 `位置来源` 字段。
  以"图形符号"开头的才算**真实位置**；以"编号文字"开头的是**回退值**（多半意味着该箱的符号没画或没识别到，位置不可信），必须列入待确认项。
  并检查 `参数.排除的箱符号图元数` 与 `箱位来源` 是否符合预期。
- **覆盖范围连续性检查**：断口恰好落在楼层线上时，用端点直推法直接判定归属（断头落在哪层就覆盖到哪层），不设"二选一"的模糊层。
  覆盖楼层天然是一个连续闭区间——不跨断口、不合并相邻连续体、不产生中间的空洞。
- **有真值表就必须反查（2026-09-11 新增）**：手上有已定稿的标准地址表时，
  跑 `verify_coverage_truth.py <标准地址表.xlsx> <覆盖范围.json>` 逐箱比对，要求 **0 个 `✗ 不一致`**；
  全部为 `✓ 一致` 才算通过（判定只有`一致`/`不一致`两档，不存在模糊档）。
- **入户规模双来源必查（走读取标注（图签形态） / 采集表路径时，2026-09-12 新增）**：
  逐栋比对 `(单元数, 层数, 每层户数)`，**不得用聚合计数当判据**（图纸常把同一栋画两遍，聚合数量会翻倍）。
  不一致即列待确认项，附双方数值与坐标。详见 [references/titleblock_and_intake_table.md](references/titleblock_and_intake_table.md)
- **图纸重复绘制与楼名笔误检查（2026-09-12 新增）**：
  统计楼名标注的出现次数分布并给出基准值；若某楼名出现次数**高于基准**，同时采集表里有、图上完全没有的楼名**成对出现**，
  即定位为图签楼名笔误 → 列入待确认项，经用户裁定后用显式覆盖表（`--patch`）补录，并在输出中留痕。
- **图签内文字可信度检查（2026-09-12 新增）**：图签的图名、说明栏、"共覆盖住户 N 户"等文字可能整段从别的图纸复制未更新。
  与图签层成对标注或采集表冲突时，**一律不作户数依据**，只作线索。
- **地址树行数恒等式（2026-09-12 新增）**：若交付形态是九级地址树，必须校验
  `行数 = 1 + 1 + 楼栋数 + 单元数 + Σ层数 + Σ户数`，不成立即报错停止。
- **矛盾检查**：以上校验中发现的任何矛盾（数据内部不一致、跨图标注不同等），立即列入待确认项请求人工介入

**C5 扩展（2026-09-18 实跑修复）**：原实现把「户数 / 布线两列皆空」的层行**直接从清单过滤**——
那些层既不出现、也无人告知，出表后凭空消失且零说明，与 Step 1c「某层无户数标注即不生成户号，
**列待确认项**」直接冲突。现改为**逐条登记**（楼栋/单元/层名）并把该项判 **WARN**：
本项只报事实、不下结论（地下车库 / 设备层 / 储藏层都可能是合法图面事实）。
要点：**「图上确实没有户数」与「我没读到户数」必须可区分**。

**C10 图签第二来源逐栋比对（2026-09-18 实跑新增）**：把 `read_titleblock_households.py` 读出的

**C10 字段级口径（八十一，2026-09-19 实跑修复）**：比对应按**字段级可比性**执行——
**双非空且不等**才计矛盾；单侧不可读（如图标法系统图不标户数 ⇒ 系统图侧为 null）
显式登记「? 单侧不可读，无法比对」，**不计 FAIL、不冒充已核**；可比字段全一致但
