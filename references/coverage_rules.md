# 覆盖范围：判定规则

> **原则**：助手优先从数据自行判定覆盖范围，能算则算、算出即用。仅当所有可用方法均无法给出可信结论时，才整理已知事实列为待确认项交用户裁决。不得编造、不得在数据不明确时瞎猜。

## 零、前置约束

> 以下约束来自实测事故与重构。任何一条不满足，竖线法 / V型计算 的输出都不成立。

**0.1 连线数据必须来自电信图层，不得扫描全图。**
- 实测事故：不区分图层提取 LINE/LWPOLYLINE 时，绝大多数"竖干线"其实来自**垃圾图层 `0`** 与 WALL/WINDOW/家具/热水器等**建筑图层**，真正的**通信图层命中 0 条**。在这种数据上做任何竖线法追踪都不可能对。
- 必须显式传 `--wire-layer`（如 `RX-wire.通讯,WIRE-通讯`），并核对脚本输出的 `线段图层来源统计`。
- 若"参与分析"的图层里出现 `0` / 建筑 / 图框 / 家具，本次结果**不可用**，必须调整图层重跑。

**0.2 覆盖分界只能由竖干物理断口或逐条连线确定；严禁按安装楼层排序切分。**
- ❌ 错法：把同单元的两个箱"按安装楼层从低到高排序"，再把楼层从下往上顺序切开。这是**工程推断**，不是读图，已明令禁止。
- ✅ 对法：找竖干物理断口（`analyze_coverage.py` 输出 `竖干断口`），断口位置即分界；每箱认领"箱的 y 落在其中的那个连续体"。
- **反例（实测案例）**：当竖干断口中点恰好与某条楼层线重合时，按断口切分与按安装层排序切分会给出**不同的分界楼层**（前者把断口层及其以上归高箱，后者从楼层序列中点切开）。而这两种切法的**总户数往往完全相同**。
- ⚠️ 因此 **总户数吻合完全无法验证对错，必须比对分界楼层。**

**0.3 不得把断口两侧的连续体合并成一个覆盖范围。**
- ❌ 错法：取"分纤箱附近全部竖干线段的 `min(y) ~ max(y)`"作为覆盖范围。断口两侧被合并后，**同一单元的两个箱会得到完全相同的覆盖范围**。
- ✅ 对法：竖干按 x 聚类后再按 y 断口切成**连续体**，每个箱只认领属于自己的那一个连续体。
- `analyze_coverage.py` 会输出 `竖干连续体` 与 `连续体被多箱认领` 两个字段；**后者非空即为异常**，必须复核。

**0.4 必须先确认"箱在哪"：编号文字坐标 ≠ 箱的位置。**
- 实测事故：某图纸的全部 `FX##` 编号文字**只出现在总图区**——那里是"光交 → 各箱"的**拓扑图，没有竖干**；而竖干与箱符号在**系统图区**。用编号文字坐标当箱位，结果是**每个分纤箱都报"附近未找到竖干"**。
- 必须区分三种"位置"：
  | 用途 | 取哪里 | 参数 |
  |---|---|---|
  | 楼栋/单元归属 | **分纤箱编号**查对照表（权威，不做几何推断） | `--bldg-map` |
  | 箱的物理位置 | 系统图里的**图形符号** | `--fx-symbol-layer` |
  | 楼层刻度 | 系统图自己的楼层标注（排除总图区文字） | `--total-pad` |
- 符号判别：箱符号为闭合多段线小矩形。同图层另有大量 `len=0` 的 LINE（皮线锚点），若一并当箱，一个单元会凭空多出十几个箱。判别结果会写入输出的 `参数.箱位来源`，未命中时逐级降级并告警。
- ⚠️ 若符号层同时被写进 `--wire-layer`，箱体的左右竖边会被当成"竖干"，认领到一个**虚假的矮连续体**（症状：覆盖楼层全空）。脚本已主动排除符号图元，并在输出里给 `排除的箱符号图元数`。

**0.5 断口恰好落在楼层线上时，用竖线端点直推（三步走），不做模糊归属。**
- 实测：断口端点与楼层线的偏差常在一个楼层带以内，且断头归上段或下段的情况都存在——源图两种画法都有，因此不能靠"断口离哪条楼层线近"来猜。
- ✅ 三步走（`analyze_coverage.py` 已实现，2026-09-12 重构）：
  1. 先知道每层 y 坐标（楼层刻度）；
  2. 用区间法求分纤箱安装楼层（与总图对照表校验）；
  3. 从分纤箱所在竖干向上/向下找断头，**断头 y 用区间法测出所在层** → 覆盖楼层 = 下界层~上界层 闭区间。
  断头是区间不是点，**用竖线末端端点测层，不用中点**（中点落在层带交界处无物理意义）。

**0.6 验收到此为止：用已定稿的标准地址表反查。**
- 有官方/已定稿标准地址表时，表里"户 → 分纤箱"的聚合结果就是**覆盖范围真值**，不必靠人肉翻表。
- 用 `scripts/verify_coverage_truth.py <标准地址表.xlsx> <覆盖范围.json>`（或 `ftth.py verify-truth`）逐箱比对，
  两档结论：`✓ 一致` / `✗ 不一致`；退出码 0/2 可做门禁。
- 有已定稿标准地址表时，反查结果应为 0 个不一致。

**0.7 覆盖表（光交配纤表 / 皮线→箱映射）不作覆盖判据；图上直写的箱体覆盖起止层可作判据。**
- **覆盖表**（如 `9P(1-8) 至01#箱`，信号 `coverage_table`）只说明「皮线编号 → 分纤箱」的**归属**，
  **不给出分纤箱的覆盖楼层区间**，不能替代竖线法 / V型计算。它是**参考线索**：可用于交叉核对归属，不得作为覆盖结论写入成果表。
- **箱体覆盖起止层直写**（如 `覆盖 -1F~9F`，信号 `cover_range_annotation`）是图上**直接写出的覆盖楼层区间**，属「读取标注」的覆盖形态，**可以**作为覆盖判据，且是覆盖范围的首选来源（比几何推算更可靠）。
- 两者容易混淆：都含 `覆盖` 字样，但一个给**归属**、一个给**楼层区间**。判据只认后者「含两个楼层标记」的形式。

## 一、单箱单元

单箱单元无需判断覆盖范围：该分纤箱覆盖本单元全部住户楼层（1F至顶层）。此为**直读结论**（因单元内仅一个分纤箱，覆盖范围唯一确定）。

## 二、双箱单元覆盖范围

当一个单元有两个分纤箱（低箱+高箱）时，需确定各自覆盖哪些楼层。

> **方法选择规则（2026-09-12 用户裁决更新）**：方法按测量原理命名（竖线法/V型计算），按信号选方法，不设固定优先级、不用小区名冠名：
>
> | 信号 | 用什么方法 |
> |---|---|
> | 竖干连线干净（独立电信图层，可追踪） | **竖线法**（analyze_coverage.py，竖干断口/端点直推） |
> | 皮线米数标注呈 V 形（`Xm*N` 随楼层先减后增） | **V型计算**（analyze_coverage_vshape.py，米数谷底） |
> | 两信号均在 | **必须并跑两法并比对**；不一致列入待确认，**不得自动择一** |
> | 两信号均缺 | 整理已知事实列为待确认项交用户 |

### 竖线法（竖干追踪/端点直推）——信号：竖干连线干净

> 以下规范基于实战验证，适用于"竖线法"的执行细节。

**1. 竖主干线追踪**
- 系统图区通常存在一根竖主干线，由多条 LWPOLYLINE 段或多条 LINE 首尾相接组成
- 逐条提取所有 LWPOLYLINE（注意 `get_points()` 返回五元组 `(x, y, bulge, start_width, end_width)`，需取 `[p[0], p[1]]` 提取坐标）和 LINE 实体
- 按端点坐标匹配（容差 ≤ 2 单位）拼接连续线段，还原完整的竖主干
- **竖主干上的断口即为覆盖分界**：断口上方的线段归一个分纤箱、断口下方归另一个

**2. 皮线（入户线）判定——按连接关系，不按几何阈值**
- ❌ **错误做法**：用 `abs(dy) < threshold` 等刚性几何阈值区分"横线/斜线"，超出阈值的线段直接丢弃
- ✅ **正确做法**：按**连接关系**判定——皮线的特征是：一端落在竖主干线的 x 坐标上（容差 ≤ 3），另一端落在住户设备 INSERT 的 x 坐标上
- 特殊情况：B1/WF 等极端楼层的皮线可能以斜线形式接入竖主干底端/顶端，落差可能超过 10 单位，但只要满足连接关系即为有效皮线
- 脚本必须输出"已分类皮线"和"未分类线段"两组清单，未分类线段供人工检查

**3. 竖干线段与楼层映射**
- 提取楼层文字标注坐标（如"1F"@"(x, y)"），建立 y 坐标→楼层映射表
- 竖干线段的 y 范围即覆盖楼层范围：`y_top` 对应最高楼层、`y_bottom` 对应最低楼层
- 注意 DXF 中 y 轴方向：多数图纸楼层越高 y 值越大，验证时先确认方向一致性

**4. 覆盖分界判定——端点直推（竖线法核心算法，2026-09-12 用户裁决确立）**
- **端点直推法（三步走）**：① 每层 y 坐标；② 区间法求分纤箱安装楼层；③ 从安装楼层沿竖线向上/下延伸，竖线的**断头落在哪层就覆盖到哪层**——低箱顶端断头=覆盖最高层，底端断头=覆盖最低层
- ❌ **错误做法**：只看竖干线段的"断口位置"在哪个楼层标注附近，就断定分界是该层/下一层；或用"按安装楼层排序切分"代替竖干断口
- ✅ **正确做法**：竖干按 x 聚类后按 y 断口切成**连续体**，每箱认领"箱的 y 落在其中的那个连续体"；用断头端点做区间法测层
- **皮线核对仅作交叉校验，不作分界判据**：逐条皮线追踪可用于交叉验证端点直推法的结论，但不得作为独立的分界判定依据。分界判据以竖干物理断口为准
- **反例**：某楼断口位置在9F附近，端点直推法判定分界为 8F/9F。逐条皮线核对同样显示 8F 皮线接低箱竖线底端、9F 皮线接高箱竖线顶端，两者一致

**5. 分纤箱覆盖确定**
- 每个分纤箱对应一段或多段竖干线（同一分纤箱的多段竖线合并为其完整覆盖范围）
- 竖干线断口两侧的分纤箱：断口下方竖线归低箱、断口上方竖线归高箱
- 分纤箱安装楼层由旁标文字确认（如"5F"），而非纯靠坐标推算

**6. 强制校验规则**
- 有 EQUIP-箱柜 INSERT 的楼层必须有对应皮线连接到竖主干：**有箱无皮线 → 标记为"异常"而非"0户"**
- 每个楼层的皮线数量即为该层户数
- 汇总户数 = 所有楼层皮线数之和，必须与 INSERT 总数交叉校验
- 脚本输出任何楼层为 0 户时，必须人工复查该楼层的线段数据

#### 踩坑记录：B1 漏算教训

**事故**：某栋楼 B1 层本有住户（斜皮线接入竖主干底端），脚本却输出 B1=0 户

**根因链**：
1. **直接原因**：脚本用 `abs(dy) < 5` 判定皮线类型，B1 皮线的竖直落差明显大于该阈值，被误判为"斜线"并丢弃
2. **放大原因**：分类后只统计"横线"做户数计、"斜线"类直接丢弃不回看
3. **主观原因**：脚本输出 B1=0 户时未做人工兜底核验就接受结果

**修复措施**：
1. 皮线判定改为按连接关系（端点落在竖主干 x 上 + 另一端落在设备 x 上），不依赖 dy 阈值
2. 脚本输出"未分类线段"清单供人工检查
3. 每个楼层若有 INSERT 但无皮线，标记为异常而非 0

### V型计算（皮线米数 V 形规律）——信号：皮线米数标注存在且呈 V 形

当竖干连线不可用（无独立电信连线图层/混层/断开无法追踪）时，用皮线米数的V形规律计算双箱分界。**助手自行计算并写入地址表**，结果可信则不推给用户。

#### 原理

皮线米数（图纸标注如`Xm*N`）表示从分纤箱到各层用户的皮线长度，随楼层变化呈V形：
- 以分纤箱安装楼层为谷底（米数最小）
- 向上/向下每层递增约4米（具体递增值因楼层高度而异）
- V形对称轴 = 分纤箱安装楼层

#### 实现脚本（2026-09-12）

`scripts/analyze_coverage_vshape.py`

```
# 以下为示例值，实际图层名/正则以 Step 1a 探查结果为准
& "<技能目录>\scripts\ftth.cmd" analyze_coverage_vshape.py <dxf> <out.json> \
    --text-layer <标注图层> \
    --title-pattern "<标题正则>" \
    --fx-pattern "<编号正则>" \
    --cable-pattern "^(\d+)m\*(\d+)$"
```

实测要点：

- **只读文字标注，不依赖任何线段图层** —— 连线混层（画在图层 `0`、与建筑/暖通/监控线同层）时仍可用，这是它相对方法一的核心价值
- 谷底（米数**局部极小**）= 该箱安装层；覆盖分界取**相邻两谷底之间的中位行**（对称 V 下等价于两曲线交点）
- 一个米数列含 N 个谷底 ⇒ 该单元有 N 个分纤箱
- 覆盖范围 = 本段米数行对应的楼层。V型计算的数据来源是米数列标注，覆盖范围的每一项都必须来自米数列实际存在的行——地下层在米数列无标注行，其覆盖范围不得由本方法给出。旧实现把全局最低段下方的地下层自动并入覆盖，结果中出现了米数列数据来源无法支撑的楼层，2026-09-12 用户裁决修正。如确需地下层覆盖，加 `--include-basement` 开关
- 自检：谷底对应楼层线 y 与箱号文字 y 的偏差 —— 两个独立来源互证，偏差应恒定
- 自检：段内 V 形单调性（谷底左侧递减、右侧递增）。**注意必须先分段再判**，否则双箱列会跨过下一段谷底产生假告警
- 自检口径：覆盖楼层集合与箱号在同图两处独立来源之间必须一致
- **多地块分带的边界方向不对称（2026-09-15，P0）**：系统图数据一律画在楼栋标题**上方**，故
  带的上界**不得**取「相邻带标题 y 的中点」——本带内容向上延伸的高度可能超过该间距的一半，
  中点会横穿本带内容、把顶部数层米数行与箱位标注整段切掉（→ 米数表缺行、V 谷底少 1、箱数少 1），
  且两侧各自自洽、极易被误判成「图纸自身矛盾」。上界改取**上邻带标题 y**；
  下界**必须维持中点**（下邻带内容在它自己标题上方，向下放宽必然吞邻带）。
  窗口上界还须并入米数行块顶之上的**同类标注**（箱位锚 / 楼层列）。
- **箱位锚 x 邻域门禁（2026-09-15，P0）**：箱编号常画在平面图区/箱表区，与系统图区同处一个 x 窗口
  却无几何关联；窗口放宽后邻区/邻楼编号被吞入，产生「一个单元配到远多于 V 段数的箱」的假告警。
  门禁为**尺度锚**：箱锚到其所属米数列的 x 距离 ≤ `k × 字高中位`（`--box-anchor-x-factor`，默认 10）。
  超阈者不参与箱编号归属，但**必须登记绝对距离**交人裁决，不得静默丢弃。
- **窗口上界楼层标注列兜底（2026-09-16，凤鸣朝阳事故）**：yhi_max = 带标题 y + 20×层高 只是**估算**，
  实测 8#楼（18F）顶层 17F/18F 楼层标注 y 超出该上界（387998.8 vs 388000/388006），顶层米数行被第一刀
  整段过滤 → 覆盖漏 17F/18F 两行 6 户，而 V 形单调性自检 0 告警（静默漏层）。
  修复：**单带图纸**（无邻带可混淆）上界取「yhi_max」与「本窗口 x 内楼层标注列 y 最大值 + 外扩」的较大者
  —— 楼层标注列是栋级最完整的楼层证据，存在即证明该层数据应入窗。
  **多带图纸不启用**：楼层标注列跨带（柳辛庄 1-4 图幅4 实测），放宽会把邻带楼层/箱位标注吞进窗口
  （箱数 27→42、安装层错乱），多带时维持原 yhi_max 不动。
- **自检：覆盖完整性门禁（2026-09-16，P0-12）**：每单元所有箱「覆盖楼层」并集必须等于
  「有户数标注的楼层集合」（户数标注 X户 就近配对楼层线，地下层无户数不计入）。
  不等 → 需人工裁决 + 控制台告警。**注意边界**：若窗口截断把户数标注与米数行一起切掉，
  期望集合也随之缺失，门禁无法检出（该场景由「窗口上界楼层标注列兜底」防）——门禁防的是
  「窗口内数据完整但覆盖分段/配对漏层」，与窗口兜底互为两层防线。

#### 计算步骤

1. **提取各层皮线米数**：从解析JSON中读取每层标注的皮线长度值
2. **拟合双V形**：低箱以低箱楼层为谷底拟合V形，高箱以高箱楼层为谷底拟合V形
3. **求交点楼层**：两V形曲线相交处即为覆盖分界
4. **确定分界**：交点位于两层之间时，低楼层归低箱、高楼层归高箱；无同层横跨
5. **校验可信度**：
   - 两条V形需各自能拟合（皮线数据基本符合V形走势）
   - 交点需落在两个分纤箱安装楼层之间
   - 交点附近无等距模糊层（低箱距离与高箱距离差异足够大）

**校验通过**：标注"V形计算"，写入地址表
**标注**：V形计算

#### 不可信的情况（转为待确认）

- 皮线数据缺失或不呈V形（无法拟合）
- 交点落在分纤箱安装楼层之外
- 分界层距两个分纤箱等距（差距小于一层皮线递增），无法严格区分

### 待确认（两法均不可信时）

仅当竖线法和V型计算均无法给出可信结论时，才整理已知事实列为待确认项：

| 字段 | 内容 |
|------|------|
| **问题** | 该单元低箱和高箱各自覆盖哪些楼层？ |
| **图纸已知事实** | [从DXF直读：低箱编号、低箱安装楼层、高箱编号、高箱安装楼层、各层皮线米数列表] |
| **无法自动判定的原因** | [说明竖线法为何失败（连线混层/断开）、V型计算为何不可信，给出具体原因] |
| **需要您裁决的内容** | 请确认低箱和高箱的覆盖楼层分界，以便正确分配各户到对应分纤箱 |

### 判定流程总结（信号驱动，不设固定优先级）

```
双箱单元
  ├─ 信号：竖干连线干净 → 竖线法 → 校验通过 → 直接使用
  ├─ 信号：皮线米数V形标注 → V型计算 → 校验通过 → 直接使用
  ├─ 两信号均在 → **必须并跑**两法并比对；不一致 → 待确认（不自动择一）
  └─ 两信号均缺 → 整理已知事实列为待确认项交用户
```

### 局限性说明

- 若DXF既无干净竖干、皮线米数也无规律（如非标准层高），则完全无法提供参考线索，需明确告知用户"图纸无足够信息判断覆盖范围，需用户凭施工经验或现场确认"
- 分界线附近楼层距两个分纤箱可能等距，即使皮线规律也无法严格区分——此情况转为待确认
