# 读取标注（图签形态）+ 楼宇信息采集表对照 + 九级地址树出表

> 本文记录一套与「皮线标注 / 区间法」互补的入户规模测量路径。
> **术语定位**：图签里的栋级 `N层/M户` + `N单元` 标注，属于**「读取标注」方法的一个形态（图签形态）**——
> 测量原理与层内标注直读**完全相同（直读文字）**，只是标注位于标题栏层且聚合粒度为**栋级**。
> **它不是独立方法**，方法池仍为四种（读取标注 / 区间法 / 竖线法 / V型计算）。
> 适用前提：**图纸图签（标题栏）层里直写了每栋楼的层数与每层户数**，或**项目另附《楼宇信息采集表》**。
> 两者任一存在，都比"数实体"更快、更硬；两者都在时，构成本文的三来源协议。

---

## 一、信号识别（探查阶段先看这三件事）

| 信号 | 在哪看 | 命中后的意义 |
|---|---|---|
| **图签层存在成对标注** | 文字图层名常为图框/标题栏/图签类图层；内容形如 `1#楼` + `18层/3户` + `1单元` | 可直接读出**栋级**的 `层数 / 每层户数 / 单元数`，一次读全 |
| **项目提供《楼宇信息采集表》** | xls/xlsx，列含 `小区名称 / 楼宇名称 / 楼宇单元数 / 单元层数 / 每层住户数` | 人工采集的第一来源，逐栋逐单元，粒度比图纸图签更细 |
| **一张 DXF 混排多个地块** | 图上存在段名标注（如 `N区`、`N段` 等地块标签文字），位于每段图区左上角 | 必须按 y 带分段后再归属，否则跨地块串号 |

三个信号都没有时，回到 `SKILL.md` 的方法池（区间法 / 竖线法 / V型计算）。

## 二、读取标注（图签形态）

### 2.1 几何关系（同图纸内为常数，先量后用）

图签层里每栋楼是**三行散落的文字**，在 DXF 中互不相干；脚本只能靠几何位置把它们串起来：

```
        ┌ 「N#楼」        ← 楼名（每栋一条）
        │   dy-lo ~ dy-hi          楼名在层户标注上方，x 差 ≤ dx-tol
        ├ 「N层/M户」      ← 层户标注（每栋一条）＝ 配对的基准点
        │   unit-dy-lo ~ unit-dy-hi  单元标注在层户标注下方
        └ 「N单元」        ← 单元标注（每单元一条，同栋的几条横向并排）
```

- **楼名 → 层户**：`|Δx| ≤ --dx-tol` 且 `--dy-lo ≤ Δy ≤ --dy-hi`，窗口内**必须唯一**；
  0 个或 ≥2 个一律跳过，**绝不「取最近的」**——宁可漏，不可串：串楼是静默错误，
  漏栋会在后续逐栋比对里暴露。
- **层户 → 单元**：同样先落窗口（`--unit-dx` / `--unit-dy-lo` / `--unit-dy-hi`），
  再在窗口内取最近的一个。
- 这 6 个值**随图纸坐标尺度变化**（不同图纸可差几个数量级），且**两头都要卡准**：
  太窄匹配不上（丢栋），太宽会让窗口内候选 ≥2 而同样跳过（自锁）。
  不得跨图纸套用，**也不得在文档里写死某个项目的实测值**。
- 量测方式（二选一，显式传入优先于自适应）：
  - `probe_titleblock_tolerances.py --dxf <图> --layer <图签层>`：单独量测，输出建议值与实测证据；
    加 `--band`（同下文分段写法）可让脚本**逐段交叉校验**：若有地块的窗口落在全图窗口之外，
    说明该地块用全图容差会丢户，脚本会告警并给出「该段单独出表」的命令；
  - 直接跑 `read_titleblock_households.py` 且**不传**这 6 个参数：脚本按本图自适应，
    并把推定值与依据写进结果 JSON 的「几何容差」字段，供核对。
- 量测「层户 ↔ 单元」时**必须施加方向约束，并在候选中按 |dx| + dy 等权取**——只用「x 最近」或
  只用「y 最近」实测各错一半，会量出负容差或过宽窗口（原理与证据见 `measurement_methods.md` §3.7）。
  量出的窗口若跨越 0 或自相矛盾，脚本按失败退出（退出码 2），不静默输出。

### 2.2 地块分段（y 带）

多地块混排时，一条 y 带 = 一个地块（图纸通常按行排列）。**带边界必须覆盖到该段最下方的标注**——
单元标注在层户标注下方约一个「图签行距」量级处，边界卡太紧会把单元标注漏到带外
（表现为"图上单元数为空"）。

经验做法：先按楼名标注的 y 聚出自然分段，再把每段的下界向下扩 ~100k。

### 2.3 必须检测的两个图纸质量缺陷

**① 重复绘制**
同一 `(地块, 楼栋)` 在图上可能被画两遍（甚至更多）。特征：楼名标注的**出现次数分布**如 `{2: 22, 4: 1}`。
- **后果**：把层户配置按聚合计数统计时会翻倍，**聚合计数不能作为判据**。
- **对策**：比对一律**按 `(地块, 楼栋)` 去重后逐栋进行**；出现次数分布写进质量报告。

**② 楼名笔误**
若某楼名的出现次数**高于基准**，同时另一个楼名**在采集表里有、图上却完全没有**，两者成对出现即定位笔误。
> 实测例：图签上「2#楼」出现 4 次（其余楼均 2 次），而采集表有 13 栋、图上只标出 12 栋、缺的是「3#楼」。
> 结论：3 号楼的图签楼名被误写为「2#楼」。该栋的层/户/单元标注与采集表 3 号楼完全吻合，可确证。

### 2.4 图签内其他文字不可信

图签里常有整段从**别的图纸复制未更新**的文字，例如：
- 图名写着别的楼栋/地块（如"X块光缆布线图"出现在另一地块的图纸上）
- 说明栏写着别的图纸的户数（"共覆盖住户467户"，而 467 是另一地块的户数）

**这类文字一律不得作为户数依据**，只能作线索；户数必须来自 2.1 的成对标注或采集表。

## 三、楼宇信息采集表对照协议

### 3.1 三来源与角色

| 来源 | 粒度 | 角色 |
|---|---|---|
| 《楼宇信息采集表》xls | 逐栋**逐单元** | 第一来源 |
| 图纸图签标注 | 逐栋（单元数单独读） | 第二来源（独立复核） |

（原第三来源「图纸实体 INSERT 落楼层带」已于 2026-09-13 随「不读楼层平面图、户数以系统图为准」裁定删除——INSERT 计数是示意画法，不作户数依据。）

### 3.2 比对规则

1. **逐栋**比对三元组 `(单元数, 层数, 每层户数)`，不是比总数。
2. 图签的层户标注是**每栋一条**，而采集表是**每单元一条**。比对时把采集表同栋各单元的配置取**集合**，
   图签值落在集合内即一致。
3. 全一致 → 出表。**任一不一致 → 列双方数值 + 各自坐标，交人裁定；脚本不得自动择一。**
4. 采集表小区名与图纸地块名往往不同（如 `XX小区9区` 拆为 `A段`/`B段`），
   且**一个采集表小区可能被图纸拆成多个地块分段** → 用「地块=小区名:楼号区间」显式映射，不要猜。

### 3.3 人工裁定覆盖表

图纸缺陷或图纸未表达的信息，必须走**显式覆盖表**，不得直接改数：

```json
{"A段": {"3号楼": {"单元数": 1, "层数": 18, "每层户数": 3,
                     "来源": "《…采集表》9区楼宇3；图纸该栋图名误写为2#楼"}}}
```

- 每条裁定在运行时打印 `[人工裁定] … 旧值 → 新值（来源：…）`，保证可追溯。
- 需要剔除的用 `{"删除": true}`。
- **禁止把裁定值硬编码进计算逻辑**——必须走覆盖表，便于复核与回溯。

### 3.4 键名与执行顺序（实测坑）

`read_titleblock_households.py` 的执行顺序是固定的：

```
read_titleblock（读图分段） → --patch（人工裁定） → --site-name（改名/归并） → --intake-xls（逐栋比对）
```

由此有两条硬约束：

1. **`--patch` 与 `--intake-area-map` 的键都是「分段原始名」**（如 `9块`），**不是** `--site-name` 改名后的地名
   （如 `柳辛庄恒盛名邸9区`）。写错会静默不生效（patch 静默不补、area-map 落回同名匹配）。
2. **采集表一个小区被图纸拆成多段时，映射要带楼号区间**：`--intake-area-map "9块=…9区:1-7;10块=…9区:8-13"`。
   不带区间时，逐段检查「采集表有而图签无」会把同小区其它段的楼栋成片误报。

### 3.5 出表口径：以采集表小区名为准并合并同小区的分段

图纸分段名（`N块` / FX 编号）只用于**分段与归并**，**不作为五级取值**。当采集表小区名与图纸分段名不一致，
且一个采集表小区对应图纸多个分段时，**先按采集表小区合并成一张 sheet 再出表**
（用 `--site-name "9块=X区;10块=X区;…"`，同名自动合并）。

> 实测（柳辛庄5-9）：图纸 `9块`(1~7号楼) + `10块`(8~13号楼) = 采集表 `9区`(13栋)。
> 合并后 5区/8区/9区 三张表 = 677 / 730 / 963 行，户数 486 / 516 / 676，与人工独立制作的成果逐表一致。
> 2026-09-14 独立复跑，逐值相同。

### 3.6 反查真值表前，先弄清真值表自己的结构

已定稿的标准地址表**可能是两段拼成的**：

| 段 | 六级写法 | 内容 |
|---|---|---|
| 节点行段 | `N号楼` | 楼栋行 / 单元行 / 楼层行（九级为空） |
| 户行段 | `N#楼` | 逐户行（九级＝户号） |

- 两段的五级列**可能自相矛盾**（实测：某栋的户行按**楼层分档**归了另一个五级——1~15层归 A、16~17层归 B；
  而同一 sheet 的节点行段把该栋**整体**归所在块）。这类差异**不得按笔误处理**：
  须列双方数值 + 坐标 + 楼层分布，交人裁定。
- 因是两段拼接，**行数不可与单份地址树直接比大小**（单份只各写一次），比对**只比户数**。
- 原表两段的六级写法不一致（`N号楼` / `N#楼`），交付前应统一，否则同一地址会生成两个不同字符串、破坏去重。

## 四、九级地址表 = 地址树展开

资源/沙盘系统导入用的九级地址表**不是**"每户一行"的扁平表，而是**地址树**：每一级节点自身占一行。

| 行类型 | 五级 | 六级 | 七级 | 八级 | 九级 | 行数 |
|---|---|---|---|---|---|---|
| 基础行 | — | — | — | — | — | 1 |
| 小区行 | 小区 | — | — | — | — | 1 |
| 楼栋行 | 小区 | N号楼 | — | — | — | 楼栋数 |
| 单元行 | 小区 | N号楼 | M单元 | — | — | 单元数 |
| 楼层行 | 小区 | N号楼 | M单元 | K层 | — | Σ层数 |
| 户行 | 小区 | N号楼 | M单元 | K层 | 户号 | Σ户数 |

**行数恒等式（自检门禁）**

```
行数 = 1 + 1 + 楼栋数 + 单元数 + Σ层数 + Σ户数
```

不满足即报错停止——这是最有效的"整层丢失 / 复制份数算错"检出手段。

**表形态二选一**：本形态（地址树，九级节点各占一行）与 `gen_addressbook.py` 产出的「每户一行」扁平表**不可互替**——按交付方要求选一种，不要混用。

### 4.1 填写规则

- 前 5 级（分公司/一级/二级/三级/四级）在**每一行都重复填**。
- 节点行**只填到本级**，右侧各级留**空字符串**（不是 0、不是"—"）。
- 表头、列序、列名**必须取自项目已定稿的表**（脚本用 `--header-xlsx` 取表头），禁止自造。
- 用户列（是否合作方/地址标示/局向/城郊属性/是否进线标识/进线时间/进线类型/沙盘临时表ID…）留空。

### 4.2 户号规则

- **层号 × 100 + 序号**：18 层 3 户 → `1801 / 1802 / 1803`；3 层 2 户 → `301 / 302`。
- 该规则已对项目已定稿表逐条回验、0 例外（回验记录见 SKILL_CHANGELOG.md）。

### 4.3 命名一致性

同一栋楼在不同层级行可能出现两种写法（层级行写 `1号楼`、户行写 `1#楼`）。
出表前**必须统一**，并在交付说明里点明原表的写法差异——否则同一地址会生成两个不同字符串，破坏去重。

## 五、复现示例（本方法的实测项目）

```
# 0) 量测 6 个几何容差（输出建议值与实测证据；可选，不跑也行——下一步缺省时会自适应）
#    多地块图建议带上 --band：脚本会逐段交叉校验，若某段窗口落在全图之外会告警。
& "<技能目录>\scripts\ftth.cmd" probe_titleblock_tolerances.py --dxf 施工图.dxf --layer <图签层> \
  --band 地块A:<ymin>:<ymax> --band 地块B:<ymin>:<ymax>

# 1) 读取标注（图签形态）+ 逐栋比对 + 人工裁定 + 地块归并
#    6 个几何容差可省略：缺省时脚本按本图自适应，并把推定值与依据写进结果 JSON 的【几何容差】字段。
#    要覆盖推定值或复现历史结果，再显式传
#      --dx-tol / --dy-lo / --dy-hi / --unit-dx / --unit-dy-lo / --unit-dy-hi。
& "<技能目录>\scripts\ftth.cmd" read_titleblock_households.py \
  --dxf 施工图.dxf --floor-layer <图签层> \
  --band 地块A:<ymin>:<ymax> --band 地块B:<ymin>:<ymax> \
  --site-name "地块A=XX小区A;地块B=XX小区B" \
  --patch patch.json \
  --intake-xls 楼宇信息采集表.xls --intake-sheet "data sheet" --intake-cols 5,6,7,8,9 \
  --intake-area-map "地块A=…A区;地块B=…B区" \
  --out households.json

# 2) 出九级地址树
& "<技能目录>\scripts\ftth.cmd" gen_9level_addressbook.py \
  --site-json households.json \
  --header-xlsx 已定稿的标准地址.xlsx --header-sheet <已定稿sheet名> \
  --addr "<分公司>,<一级>,<二级>,<三级>,<四级>" \
  --alias-idx 20 --memo-idx 26 \
  --out 标准地址表.xlsx
```

实测结果：24 栋逐栋一致；出表 3 张行数 677 / 730 / 963，户数 486 / 516 / 676，
恒等式全部成立，与人工独立制作的成果逐表一致。

## 六、待确认项模板（本路径特有）

| 字段 | 内容 |
|---|---|
| **问题** | 各单元层数户数是否一致 / 楼名笔误以哪一方为准 |
| **图纸已知事实** | 图签层该栋的成对标注值 + 坐标 |
| **参考线索** | 采集表同栋值；已定稿表中同类楼的先例 |
| **需要您裁决的内容** | 明确要确认哪一项 |

⚠ 特别注意：**图签只有一条"N层/M户"，落在同一栋的多个单元上是"按栋复制"的**。
各单元层数/户数是否真的相同，图上没有证据——单元数 > 1 时此项必须列入待确认。
