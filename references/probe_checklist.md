# Step 1a 探查清单（外移自 SKILL.md，2026-09-16 瘦身）

> 本文件是探查清单的**完整版**（含全部子项与判据）；SKILL.md 只留七项一行式 + 总图关键裁定。

对每张新DXF，先用ezdxf探查以下信息，**不预设任何项目特有参数**：

1. **图层清单**：列出所有图层名，找到含有FTTH标注信息的图层（可能是BZ、标注、文字等，每张图不同）
2. **文字实体类型**：确认标注用MTEXT还是TEXT还是两者都有
3. **文字内容采样**：随机取若干文字实体，查看实际内容格式（分纤箱编号长什么样、楼层标注格式、户数标注格式等）
4. **坐标尺度感知**：统计文字实体的x/y坐标分布范围，确定图中楼栋间距、楼层间距的数量级（不能假设固定阈值）
5. **线段实体检查**：是否有LINE/LWPOLYLINE实体，分布在哪些图层
6. **INSERT实体检查**：是否有INSERT（块引用）实体（如设备/箱柜符号），分布在哪些图层。对每个不同的块名，读取块定义内容（LINE/LWPOLYLINE/TEXT/ATTDEF）和INSERT实例的ATTRIB属性值——确认设备类型（如tag=A值为"家居配线箱"、tag=$TEXT$值为"HD"/"HDD"，**同一设备的图内文字随画图人而变，勿假定唯一写法**），不得仅凭图层名或说明文字推断设备类型
   - **设备块清单枚举**：探查阶段必须枚举所有含设备属性的INSERT块，输出完整清单：块名 × 属性值 × 坐标区域分布。同一张DXF中不同图区可能使用**完全不同的块名**表示同一种设备——但属性值（如 A=家居配线箱，$TEXT$=HD 或 HDD）一致。仅枚举已知块名会导致某些区域“消失”
   - **按属性值识别设备，不按块名**：同一设备在不同区域可能用不同块名（取决于哪台电脑/哪个人画的），但属性值一致。识别设备时必须按属性值匹配，不得硬编码块名。探查清单中应列出所有 A 属性含"家居配线箱""HDD""HD""光分路器"等关键词的块名及其区域分布
7. **分纤箱总图检查（如有，必须先做）**：部分项目DXF中包含一张分纤箱总图（通常为第一张/独立图纸），上面集中标注了各楼各单元的FX编号及安装楼层。**解析任何单栋楼之前，必须先定位并提取总图信息**：
   - **总图特征**：含楼栋单元标注（如"5#楼1单元"）、FX编号（如"FX11#"）、楼层标注（如"5F"/"13F"），三者同行或邻近对齐；可能附说明文字（如分光方式、分纤箱总数等）
   - **提取全楼FX映射表**：FX编号→楼栋→单元→安装楼层，作为后续逐栋解析的权威参照
   - **FX编号以总图为准**：后续逐栋解析时，分纤箱编号必须与总图对照；若单栋图纸标注与总图不一致，以总图为准并标记矛盾交用户确认
    - **总图定位方法**：总图通常在DXF中占据独立的坐标区域，可通过探查MTEXT中含"FX"且同时含楼栋标注（"#楼"+"单元"）的区域来定位
    - **楼栋正则必须覆盖「X#配套楼」等形式**：默认正则 `(\d+)#楼|(\d+)号楼` 匹配不到「4#配套楼」，也匹配不到无"楼"字的标题（如「1#住宅光纤入户系统图」「4#配套光纤入户系统图」），脚本会退化为"就近取最近的楼栋标注"，把配套楼的箱误归到邻近住宅楼。推荐正则 `(\d+)#.*(?:系统图|示意图)`（匹配含"系统图/示意图"且以 `X#` 开头的标题）。**探查阶段必须枚举全部楼栋标题的实际写法**（含配套楼、商业、附属楼、车库等，以及无"楼"字的标题），再据此确定 `--bldg-pattern`。
   - **`--bldg-map` 优先于任何几何归属**：`extract_fx_map.py` 的输出 JSON 可直接作为 `analyze_coverage.py --bldg-map` 的输入，用 FX 编号查表归属，彻底避开 x 区间硬切（见下文硬约束②）
    - **`--proximity-tol` 必须按实测距离设置**：`extract_fx_map.py` 默认 `--proximity-tol 200`，但不同项目 FX 编号与楼栋标注距离差异较大。**探查阶段必须先测量 FX 编号文字与最近楼栋标注的实际距离**，据此设置 `--proximity-tol`。不得盲目沿用默认值
    - **FX→楼栋映射必须人工目视核对**：修正楼栋正则加入「配套楼」后，`extract_fx_map.py` 按几何最近匹配楼栋标注，但几何最近 ≠ 正确归属。提取后必须与总图布局人工核对，矛盾项列入待确认项
